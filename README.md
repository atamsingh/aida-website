# AIDA Consulting Solutions website

Static site for https://www.aidaconsulting.ca/ — plain HTML and CSS, generated by one Python script.

## Pages

| Page | Purpose |
| --- | --- |
| `/` | Home: AI-led positioning, services, results, contact |
| `/small-business/` | Landing page for small and medium business owners (main ad target) |
| `/ai-consulting/` | Landing page for "AI consulting" searches and ads |
| `/ai-agents/` | Landing page for AI agents, assistants and RAG |
| `/data-engineering/` | Landing page for technical buyers: pipelines, warehouse, cloud cost |
| `/ai-ready-data/` | Landing page for getting data ready for AI |
| `/blog/` | Blog index and six posts |
| `/privacy/` | Privacy page (linked from the footer and the contact form) |
| `/public-sector/` | Landing page for government teams (not in the menu; reach it by URL or ads) |

## Editing

All page content lives in `build.py`. Edit it, then regenerate the HTML:

    python3 build.py

- `build.py` — content and page templates (no dependencies)
- `styles.css` — styling, light and dark themes
- `assets/contact.js` — sends the contact form to the Google Form behind it
- `assets/`, `partials/` — logo, favicon, share image, hero diagram
- `CNAME` — custom domain for GitHub Pages

Do not edit the generated `index.html` files by hand; they are overwritten by `build.py`.

## Blog

Each post is an HTML fragment in `posts/<slug>.html`, listed in `POSTS` in `build.py`
(title, summary, date, and `featured` for the four shown on the home page).
`posts/_BRIEF.md` is the writing brief: voice, allowed facts and format. Passages wrapped in
`<mark class="todo">` show highlighted in yellow: they are drafted for Atam to vet.
Remove the `<mark>` tags once checked; the build lists posts that still have them.

## Weekly post (scheduled)

A scheduled task in the Claude desktop app runs each weekday morning and follows
`posts/_WEEKLY.md`. `tools/weekly_gate.py` lets it write on one randomly chosen weekday
per week; `tools/check_site.py` must pass before it publishes. A post that fails the
checks is moved to `posts/_held/` and not published. `posts/_TOPICS.md` holds the
topic backlog and the log of what has been published.

## Booking link

`BOOKING_URL` at the top of `build.py` is the Calendly link. While it is set, every main
button reads "Book a 30-minute call"; the contact form stays as the alternative.

## Google Ads tracking

`GOOGLE_TAG_ID` at the top of `build.py` holds the Google tag id supplied by Google Ads
(currently a Tag Manager container, `GTM-...`). The tag loads on every page. The site
sends it two events: `contact_form_submit` when an enquiry is confirmed sent, and
`booking_link_click` when a booking button is clicked. Conversions are created in
Google Ads from those events. Set `GOOGLE_TAG_ID` to an empty string to remove all
tracking; the privacy page's "Advertising measurement" section follows that setting.

## Contact form

The on-page form posts to Web3Forms (`WEB3FORMS_KEY` in `build.py`), which emails each
enquiry to the address registered for that key and tells the page whether it was
accepted. The thank-you message shows only after that confirmation; otherwise the
visitor sees an error with the LinkedIn link. A copy of every enquiry is also sent to
the "Contact Information" Google Form as a backup (field ids at the top of `build.py`).

## Preview locally

    python3 -m http.server 8000

Then open http://localhost:8000.

## Deploy

Hosted on GitHub Pages from the `main` branch (Settings → Pages → Deploy from a branch → `main` / root). Every push to `main` publishes.

## Logos

`assets/logos/` holds the Stripe, Shopify, Fullscript and EDC logos shown in the
"Where our principal has worked" strip. They are trademarks of their owners and are
used only to identify past and current employers. Stripe, Shopify and EDC files come
from Wikimedia Commons; the Fullscript file comes from fullscript.com. IRCC is shown
as text because Government of Canada symbols need Treasury Board authorization.
